This page walks through how the 15 published layers were copied from the St. Johns River Water Management District's public ArcGIS Online services into PostgreSQL/PostGIS. All code is in the repository (harvest.py, layers.yaml, sql/, docker-compose.yml).

1. The source: ArcGIS REST

SJRWMD publishes its data as ArcGIS Online FeatureServers (230 services, 454 layers) under one root, also surfaced on the Florida's Water open data hub. Each layer has a REST URL ending in /FeatureServer/<id>.

BASE=https://services.arcgis.com/s8wtJX9suxFen6TA/ArcGIS/rest/services
L=$BASE/SJRWMD_Management_Area_viewLayer/FeatureServer/0
curl -s "$L?f=json" | jq '{name, geometryType, maxRecordCount, lastEdit: .editingInfo.lastEditDate, fields: [.fields[].name]}'
curl -s "$L/query?where=1%3D1&returnCountOnly=true&f=json"     # {"count":133}

The 15 layers are listed in layers.yaml under select:, each mapped to a short alias (erp, cup_station, …).

2. Harvester paging

Layers cap each response at maxRecordCount (often 1,000–2,000), so the harvester first asks for every OBJECTID, then fetches fixed-size OBJECTID ranges. This is stable even when resultOffset paging is not supported, and it is retried with backoff and a polite 0.3 s delay between requests.

ids = sorted(get(f"{url}/query", where="1=1", returnIdsOnly="true")["objectIds"])
page = min(1000, info["maxRecordCount"])
for i in range(0, len(ids), page):
    chunk = ids[i:i + page]
    data = get(f"{url}/query", where=f"{oid_field} BETWEEN {chunk[0]} AND {chunk[-1]}",
               outFields="*", outSR=3086, returnGeometry="true", f="json")   # Esri JSON, not GeoJSON
    for feat in data["features"]:
        rows.append(to_row(feat))

Esri JSON is used instead of f=geojson because the server's GeoJSON emits every polygon ring as its own polygon. The harvester rebuilds polygons from the rings by orientation (clockwise = outer ring, counter-clockwise = hole) with Shapely.

3. Reprojection

The server reprojects for us: every query passes outSR=3086 (NAD83 / Florida GDL Albers, meters), so tables store geometry in an equal-area projection suitable for area and distance work. For web use each table has a companion view in WGS84:

CREATE VIEW sjrwmd.management_area_4326 AS
SELECT source_oid, objectid, county, conservation_area, acres, ...,   -- every column except geom
       ST_Transform(geom, 4326)::geometry(MultiPolygon, 4326) AS geom
FROM sjrwmd.sjrwmd_management_area_viewlayer_0;

Doing it yourself with GDAL works too:

ogr2ogr -f PostgreSQL "PG:dbname=sjrwmd" "$L/query?where=1%3D1&outFields=*&f=json" \
  -nln sjrwmd.management_area -t_srs EPSG:3086 -nlt PROMOTE_TO_MULTI -lco GEOMETRY_NAME=geom

  source_oid bigint PRIMARY KEY,           -- the layer's OBJECTID
  objectid bigint, cur_prmt_id text, prmt_proj_nm text, prmt_stts text, county text,
  recv_dt timestamptz, prmt_decision_dt timestamptz, prmt_expir_dt timestamptz, proj_acres double precision, ...,

  _source_url text, _hub_item_id text, _fetched_at timestamptz, _source_last_edit timestamptz, _hash text);

CREATE VIEW sjrwmd.erp AS SELECT * FROM sjrwmd.environmental_resource_permit_erp_0;   -- friendly alias

5. Provenance

Every row carries where and when it came from, and every run is logged:

-- per row
_source_url        -- the layer REST URL
_hub_item_id       -- Hub dataset id, when one exists
_fetched_at        -- when this mirror fetched it
_source_last_edit  -- the layer's editingInfo.lastEditDate at fetch time
_hash              -- md5 of attributes + geometry, used for change detection
-- per layer / per run
SELECT name, server_count, last_edit_date, last_harvested_at, last_status FROM meta.layer_registry;
SELECT name, started_at, status, fetched, inserted, updated, deleted, seconds FROM meta.harvest_run ORDER BY run_id DESC;

A load counts as complete when the number of rows loaded equals the server's returnCountOnly count; the map shows that match for every layer.

6. Incremental updates

On each run, a layer is skipped when its lastEditDate, server count and schema signature are all unchanged. Otherwise it is fetched into a staging table and merged by hash in one transaction:

INSERT INTO sjrwmd.environmental_resource_permit_erp_0 AS t SELECT * FROM stage
ON CONFLICT (source_oid) DO UPDATE SET (prmt_stts, ..., geom, _hash, _fetched_at) =
  (excluded.prmt_stts, ..., excluded.geom, excluded._hash, excluded._fetched_at)
WHERE t._hash IS DISTINCT FROM excluded._hash;           -- only rows that really changed
DELETE FROM sjrwmd.environmental_resource_permit_erp_0 t WHERE NOT EXISTS (SELECT 1 FROM stage s WHERE s.source_oid = t.source_oid);
python harvest.py                 # all 15 layers, skip unchanged
python harvest.py --only erp      # one layer
python harvest.py --force         # ignore lastEditDate and reload

7. Example SQL

Run against this mirror (Oct 28, 2026); all of these use the friendly alias views.

-- ERP permits within 1 km of a point (lon/lat in downtown Orlando), nearest first
SELECT cur_prmt_id, prmt_proj_nm, prmt_stts, round(ST_Distance(e.geom, p.g)) AS meters
FROM sjrwmd.erp e, (SELECT ST_Transform(ST_SetSRID(ST_MakePoint(-81.38, 28.54), 4326), 3086) g) p
WHERE ST_DWithin(e.geom, p.g, 1000) ORDER BY meters LIMIT 10;

-- Consumptive-use permit stations inside each district management area
SELECT a.conservation_area, count(*) FROM sjrwmd.management_area a
JOIN sjrwmd.cup_station c ON ST_Intersects(a.geom, c.geom) GROUP BY 1 ORDER BY 2 DESC LIMIT 10;

-- ERP permits issued per county per year since 2020
SELECT county, extract(year FROM prmt_decision_dt)::int AS yr, count(*)
FROM sjrwmd.erp WHERE prmt_decision_dt >= '2020-01-01' GROUP BY 1, 2 ORDER BY 1, 2;

-- Acres of 2020 land use by code inside conservation easements
SELECT l.lucode, round(sum(ST_Area(ST_Intersection(l.geom, e.geom))) / 4046.86) AS acres
FROM sjrwmd.land_use_2020 l JOIN sjrwmd.conservation_easement e ON ST_Intersects(l.geom, e.geom)
GROUP BY 1 ORDER BY acres DESC LIMIT 10;

-- Kilometers of mapped stream flowpath per management area
SELECT a.conservation_area, round(sum(ST_Length(ST_Intersection(s.geom, a.geom))) / 1000) AS km
FROM sjrwmd.management_area a JOIN sjrwmd.stream_flowpath s ON ST_Intersects(s.geom, a.geom)
GROUP BY 1 ORDER BY 2 DESC LIMIT 10;

8. Reproduce it with Docker Compose

git clone https://github.com/knightchrism/sjrwmd-open-data && cd sjrwmd-open-data
cp .env.example .env               # set your own passwords; .env is never committed
docker compose up -d db            # PostGIS 17-3.5; runs sql/01_init.sql on first start
python -m venv .venv && .venv/bin/pip install -r requirements.txt
set -a; . ./.env; set +a
.venv/bin/python harvest.py        # ~730k features, roughly 20-40 minutes
docker compose up -d featureserv martin   # OGC API Features on :9000, vector tiles on :3000

Rebuild the map tiles and downloads with scripts/build_tiles.sh (tippecanoe) and scripts/export.sh (GDAL). On Windows, use Docker Desktop and keep the clone in a local folder such as C:\dev (not OneDrive).
