AI / MCP

sjrwmd-mcp is a small, read-only Model Context Protocol server. Any MCP-capable assistant can call it to query the 15 layers: find features near a point, in a bounding box, by attribute, or count them by a field. By default it reads the published GeoParquet with DuckDB (no database needed); set DATABASE_URL to use your own PostGIS instead.

Use with GitHub Copilot in VS Code

  1. Install uv (it provides uvx), and use VS Code with the GitHub Copilot extension.
  2. Add the server. Clone this repo and open it in VS Code: it already contains .vscode/mcp.json. Or create that file in any workspace: 
    {
  "servers": {
    "sjrwmd": {
      "type": "stdio",
      "command": "uvx",
      "args": ["--from", "git+https://github.com/knightchrism/sjrwmd-open-data#subdirectory=mcp", "sjrwmd-mcp"]
    }
  }
}
    VS Code shows a Start link above the server entry; click it (or run MCP: List Servers). The first start downloads the package; each layer's data (0.06–310 MB) is cached in ~/.cache/sjrwmd-mcp the first time it is queried.
  3. Open Copilot Chat in Agent mode. Open the Chat view (Ctrl+Alt+I / ⌃⌘I) and pick Agent in the mode dropdown.
  4. Enable the tools. Click the tools icon in the chat box and make sure the sjrwmd tools are checked (list_layers, describe_layer, find_near, features_in_bbox, get_feature, search_attributes, count_by). Copilot asks for approval the first time it runs a tool.
  5. Ask questions. For example (results below are from the recorded runs):
    • "Which permitted water-use wells are within 2 miles of downtown DeLand?" → find_near on cup_station returns wells sorted by distance_miles, with permit ids, station type and status.
    • "Which counties have the most ERP permits?" → count_by returns Duval 15,438, Brevard 12,520, Orange 12,382, …
    • "Show the trails in the Lake Norris Conservation Area." → search_attributes finds the area, then features_in_bbox returns 6 trail segments with blaze colour, allowed uses and miles.
    • "Which monitoring stations are near Lake George?" → find_near on edr_station returns station names, category and active/inactive status.

Other clients

Claude Desktop (claude_desktop_config.json) and Cursor (~/.cursor/mcp.json or .cursor/mcp.json) use the same command:

{
  "mcpServers": {
    "sjrwmd": {
      "command": "uvx",
      "args": ["--from", "git+https://github.com/knightchrism/sjrwmd-open-data#subdirectory=mcp", "sjrwmd-mcp"]
    }
  }
}

Run it by hand: uvx --from "git+https://github.com/knightchrism/sjrwmd-open-data#subdirectory=mcp" sjrwmd-mcp (speaks MCP over stdio). With pip: pip install "git+https://github.com/knightchrism/sjrwmd-open-data#subdirectory=mcp".

Tools

ToolWhat it does
list_layersThe 15 layers with type, feature count and field names
describe_layer(layer)Fields with types, source and download links
find_near(layer, lat, lon, radius_miles)Features within a radius (max 50 mi), nearest first
features_in_bbox(layer, bbox)Features intersecting [min_lon, min_lat, max_lon, max_lat]
get_feature(layer, id)One feature with its GeoJSON geometry
search_attributes(layer, field, value | contains)Exact or case-insensitive substring match
count_by(layer, field)Counts per value, most common first

Results are "GeoJSON-lite": attributes plus a centroid lat/lon, and full geometry only when asked (include_geometry). Limits default to 50 and cap at 500.

Safety

Read-only by design: fixed SQL templates, layer and field names checked against a whitelist, every user value passed as a bound parameter, and on PostGIS a read-only session with a 30 s statement timeout.

What about a chat box on this page?

A public web chat would need a hosted language model (and someone paying for it), so it is not included. The server runs on your machine, inside the assistant you already use.

About

An open-source, reproducible mirror of 15 public GIS layers from the St. Johns River Water Management District (SJRWMD), which covers 18 counties of northeast and east-central Florida.

Why these 15 layers

Five polygon, five point and five line layers, chosen for usefulness and for clean API use: stable IDs, typed date and status fields, and easy spatial joins. Permits (ERP, CUP, wells, reuse), monitoring stations, district lands, 2020 land use and the stream network.

How it works

  1. A Python harvester pages each ArcGIS REST layer by OBJECTID and loads typed tables into PostGIS, with provenance on every row.
  2. Every load is checked against the server's feature count. All 15 match.
  3. tippecanoe turns each layer into a single PMTiles file, served directly by GitHub Pages and drawn with MapLibre GL. No tile server.
  4. GDAL exports GeoPackage, GeoParquet and CSV for the downloads.

Full walkthrough: How it was loaded into PostGIS. Source code: github.com/knightchrism/sjrwmd-open-data (MIT).
